# ADR-0001: Локальное модульное приложение на C++/Qt6 и SQLite

## Контекст и постановка задачи

InvestLab предназначен для исторического моделирования инвестиций в акции и ETF на macOS без учётных записей и реальных торговых операций. Необходимы изоляция расчётов от интерфейса, локальная история сценариев и управляемый внешний источник цен. Следует выбрать архитектуру, доступную небольшой команде.

## Драйверы решения

- Ограничение платформой macOS и языком C++ (REQ-PORT-001).
- Проверяемый и воспроизводимый движок стратегий (REQ-FUNC-006–009).
- Локальное хранение без сервера (REQ-FUNC-012–013, REQ-REL-001).
- Минимизация инфраструктурных расходов; понятные ошибки получения цен (REQ-FUNC-017–018).

## Рассмотренные варианты

1. C++/Qt6 Widgets + Engine + Data Provider + SQLite в одном desktop-приложении.
2. C++ desktop + отдельный сервер + PostgreSQL.
3. Веб-приложение с удалённой БД и web GUI.

## Итог решения

**Выбран вариант 1 (предложен к согласованию).** Приложение организуется как слои: Qt6 Widgets GUI → сервис моделирования / `investlab_core` → модуль котировок и SQLite-хранилище. Для расчёта не требуются сеть и база, если цены уже получены и переданы как данные. Сеть применяется к загрузке истории; SQLite — к сохранению пользовательских результатов. Архитектура соответствует учебному прототипу, но не означает, что все функции уже завершены.

### Последствия

- **Хорошо:** простой локальный запуск, независимое тестирование движка, отсутствие облачной инфраструктуры.
- **Плохо:** приложение ограничено macOS; пользователю нужно учитывать локальные резервные копии SQLite.
- **Нейтрально:** внешний API остаётся заменяемым; конкретный провайдер утверждается отдельно.

### Подтверждение

Проверка структуры CMake/Qt6, тест моделирования с фиксированными котировками, тест сохранения и восстановления сценария, демонстрация ошибочного периода цен без запуска недостоверного расчёта. Статус ADR обновляется на `accepted` только после фактического согласования.

## Плюсы и минусы вариантов

### Локальный C++/Qt6/SQLite
+ Нет серверных расходов, естественная интеграция с имеющимся C++ проектом.
− Нет облачной синхронизации, поддержка macOS.

### Desktop + сервер
+ Централизованные данные, многопользовательская архитектура.
− Сложнее эксплуатация и выше стоимость для учебного MVP.

### Web + облачная БД
+ Доступ с нескольких устройств.
− Не соответствует закреплённой платформе и увеличивает объём работ.
