# InvestLab — системные требования (ЛР №4)

**Основание:** SRS версии 0.2 из ЛР №3 и существующие карточки требований. Документ распределяет требования по проектным подсистемам и не заменяет SRS. **Статус:** проект согласования.

## Functional requirements

| SRS IDs | Component and responsibility | Acceptance verification | Priority |
|---|---|---|---:|
| REQ-FUNC-001–005, 011 | GUI/Portfolio: акции, ETF, период, капитал, доли, дробные акции | Проверка формы и долей | 10 |
| REQ-INT-001, REQ-FUNC-017–018 | MarketData: загрузка истории, запрет расчёта при неполных котировках | Негативный тест отсутствующих цен | 10 |
| REQ-FUNC-006, 010 | Engine: Buy & Hold, комиссия | Ручной контроль сделки и стоимости | 10 |
| REQ-FUNC-007 | Engine: DCA, регулярные денежные потоки | Тест разных интервалов взносов | 20 |
| REQ-FUNC-008 | Engine: SMA | Тест границ истории и сигналов | 30 |
| REQ-FUNC-012–013 | Storage: SQLite, сохранение портфеля и истории | Save/restore test | 20 |
| REQ-FUNC-014–016 | GUI/Results: показатели и график капитала | Контроль данных графика и показателей | 20 |
| REQ-FUNC-009 | Engine: RSI | Тест расчёта индикатора и сигнала | 30 |

## Non-functional requirements

| SRS ID | System property | Verification / architectural decision |
|---|---|---|
| REQ-PORT-001 | macOS desktop | Qt6/C++ сборка, без серверного развёртывания |
| REQ-SEC-001 | Отсутствие реальных торговых операций | Отсутствие брокерских интерфейсов размещения заявок |
| REQ-REL-001 | Сохранность локальных результатов | SQLite-транзакции и тест восстановления |
| SRS §3.3.1 | Производительность | Числовая цель пока не согласована; измеряется на выбранном Mac |
| SRS §3.3.4 | Доступность | Локальная история доступна без сети, API требует подключения |
| SRS §3.3.5 | Диагностика ошибок | Сообщения об ошибках без раскрытия ключей API |

Исходный набор F01–F10, включая RSI.
